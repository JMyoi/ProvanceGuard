# Provenance Guard — Planning / Spec

> Written **before** implementation (Milestone 2). This document is the canonical spec
> that later milestones implement against, and the source material for prompting AI tools.

Provenance Guard is a backend service a creative-sharing platform can call to classify
whether a piece of **text** was written by a human or generated by AI, express that
verdict as a *calibrated confidence score* rather than a binary flag, surface a plain
-language **transparency label** to readers, and let creators **appeal** a classification.

A guiding principle runs through every decision below: **on a writing platform, falsely
labeling a human's work as AI is worse than missing some AI text.** The scoring bands,
the label copy, and the appeal path all lean cautious because of that asymmetry.

---

## 1. Detection Signals

The pipeline uses **two genuinely independent signals** — one *semantic*, one *structural*.
Their independence is the point: each is blind to what the other sees, so combining them is
more informative than either alone, and their *disagreement* is itself useful signal.

### Signal 1 — Groq LLM classifier (semantic / holistic)
- **What it measures:** whether the text *reads* as machine-generated — hedged, over
  -balanced, uniformly "safe" prose, formulaic transitions ("It is important to note…",
  "Furthermore…"), absence of a personal stake or idiosyncratic voice.
- **Why it differs human↔AI:** humans take positions, wander, and write with a
  recognizable voice; instruction-tuned LLMs default to balanced, tidy, low-risk prose.
- **Output:** `llm_score` — a float in `[0,1]` = P(AI-generated), plus a short rationale
  string. Model: `llama-3.3-70b-versatile`, `temperature=0` for stability.
- **Blind spot:** can be fooled by lightly human-edited AI text; may over-flag formal or
  non-native-English human writing; non-deterministic and costs an API call.

### Signal 2 — Stylometric analyzer (structural / statistical, pure Python)
- **What it measures:** three measurable statistics of the text:
  - **Sentence-length variance** — how much sentence lengths differ (AI is uniform).
  - **Type-token ratio (TTR)** — vocabulary diversity = unique words / total words.
  - **Punctuation density** — punctuation marks per word (AI tends to be moderate/uniform).
- **Why it differs human↔AI:** AI prose is statistically *even* — similar sentence
  lengths, moderate diversity. Human prose is *bursty* — short punchy sentences next to
  long ones, more variable diversity and punctuation.
- **Output:** `stylometric_score` — a float in `[0,1]` = P(AI-generated), derived by mapping
  each metric to an AI-likelihood sub-score and averaging them.
- **Blind spot:** unreliable on **short text** (< ~40 words — too little data); a
  **repetitive, simple-vocabulary human poem** looks "uniform" and can be mis-scored as AI;
  polished human academic prose scores high.

### Why this pairing
One reads *meaning*, one counts *structure* — they fail in different situations, so they
rarely fail together. When they strongly disagree, the system deliberately refuses a
confident verdict (see §2).

## 2. Uncertainty Representation & Confidence Scoring

### What the score means
`confidence` is defined as **P(AI-generated), in `[0,1]`**. It is a *design decision first*:
- `0.5` means **"we genuinely cannot tell"** — not a coin flip we're hiding, an honest shrug.
- A `0.95` should feel to a user like a strong claim; a `0.55` should feel like a hedge.
The **"uncertain" band is intentionally wide** so borderline cases resolve to "we're not
sure" rather than an accusation.

### Combining the two signals
```
combined = 0.65 * llm_score + 0.35 * stylometric_score
```
- **LLM weighted higher (0.65):** it reasons about meaning holistically and is the more
  reliable single indicator; stylometry is noisier (especially on short text), so it gets
  0.35 as a corroborating structural check.
- **Disagreement guard:** if `abs(llm_score - stylometric_score) > 0.4`, the signals
  materially conflict → the result is **forced into the "uncertain" band** regardless of the
  combined average. Two blind detectors that disagree is exactly when we should *not* be
  confident. This directly serves the false-positive asymmetry.

### Thresholds (attribution buckets)
| combined score | attribution     | meaning to user            |
|----------------|-----------------|----------------------------|
| `>= 0.75`      | `likely_ai`     | Likely AI-generated        |
| `0.45 – 0.75`  | `uncertain`     | Not enough certainty       |
| `< 0.45`       | `likely_human`  | Likely human-written       |

The AI threshold (0.75) sits higher than the human threshold's mirror would (0.25) — the
band is **asymmetric on purpose**: it takes more evidence to call something AI than to leave
it alone, because a false "AI" accusation is the costly error.

### How we'll validate it's meaningful (M4)
Run the 4 assignment test inputs (clear-AI, clear-human, formal-human, edited-AI). Success =
clear-AI lands in `likely_ai`, clear-human in `likely_human`, and the two borderline cases
land in `uncertain` (or at least well away from the wrong extreme), with each signal's score
printed separately so we can see which one drives each result.

## 3. Transparency Label Design (three variants)

Plain language, aimed at a **non-technical reader**, with confidence shown as a rounded
percentage. Copy leans cautious and never states a verdict as fact.

**High-confidence AI** (`attribution == likely_ai`):
> ⚠️ **Likely AI-generated.** Our analysis suggests this content was probably created with
> AI assistance (confidence: {pct}%). This is an automated estimate, not a certainty — the
> creator can appeal if they believe this is wrong.

**High-confidence human** (`attribution == likely_human`):
> ✅ **Likely human-written.** Our analysis found no strong signs of AI generation
> (confidence: {pct}% that this is AI). This is an automated estimate and not a guarantee of
> authorship.

**Uncertain** (`attribution == uncertain`):
> ❓ **Uncertain origin.** Our signals disagree or are inconclusive, so we can't reliably say
> whether this was written by a human or AI (confidence: {pct}% that this is AI). We're
> showing this openly rather than guessing. The creator can provide context via an appeal.

`{pct}` = `round(confidence * 100)`. For the human label the percentage is framed as
"% that this is AI" so a low number reads reassuringly.

## 4. Appeals Workflow

- **Who can appeal:** the creator of a submitted piece (identified by `content_id`; in a real
  system tied to the authenticated `creator_id`). No re-classification is automated.
- **What they provide:** `content_id` + `creator_reasoning` (free-text explanation, e.g.
  "I'm a non-native speaker; my formal style isn't AI").
- **What the system does on receipt:**
  1. Look up the original decision by `content_id` in SQLite (404 if unknown).
  2. Update that content's `status` → `under_review`.
  3. Write an **appeal audit entry** linked to the original decision (same `content_id`),
     recording the reasoning, a timestamp, and the original attribution/confidence.
  4. Return a confirmation `{ content_id, status: "under_review", message }`.
- **What a human reviewer sees** (via `GET /log`): the original classification row
  (both signal scores + combined + attribution) sitting next to the appeal row (reasoning +
  timestamp), so the contested decision and the creator's context are side by side.

## 5. Anticipated Edge Cases (specific, not generic)

1. **Repetitive, simple-vocabulary human poem.** Deliberate repetition and short lines drive
   sentence-length variance and TTR *down*, which the stylometric signal reads as
   "AI-uniform." The LLM may partly disagree — and that disagreement (>0.4) trips the guard
   in §2, pushing the result to **uncertain** instead of a false AI verdict. Documented
   known limitation.
2. **Very short submission (a tweet-length blurb, < 40 words).** Stylometry has too few
   sentences/tokens to be statistically meaningful, so its score is near-random. Mitigation:
   below a minimum word count we down-weight (or flag) the stylometric signal and lean on the
   LLM, and bias toward `uncertain`.
3. **Lightly human-edited AI text.** A human polishing AI output blurs both signals; this is
   *meant* to land mid-range (uncertain), which is the honest answer — perfect detection here
   is unsolved.

## Architecture

```
SUBMISSION FLOW
                                 raw text          raw text
POST /submit  ──rate limit──►  ┌─► Signal 1: Groq LLM ──llm_score(0-1)──┐
{text,             (429 if     │                                        ▼
 creator_id}        over)      └─► Signal 2: Stylometry ─styl_score(0-1)─► Confidence
                                                                          Scorer
                                                                            │ combined
                                                                            │ score +
                                                                            │ attribution
                                                                            ▼
                                                                     Label Generator
                                                                            │ label text
                          ┌─────────────────────────────────────────────────┤
                          ▼                                                   ▼
                   SQLite Audit Log  ◄──row(scores,attribution,status)   JSON Response
                                                                    {content_id,attribution,
                                                                     confidence,signals,label}

APPEAL FLOW
POST /appeal ──► lookup content_id ──► set status="under_review" ──► append appeal row ──► {status,message}
{content_id,          in SQLite          (original decision           to Audit Log
 creator_reasoning}                       preserved, linked)
```

**Narrative.** *Submission:* raw text clears the rate limiter, fans out to the Groq LLM and
the stylometric analyzer (each returns a 0–1 AI-likelihood), the confidence scorer combines
them into one calibrated score + attribution bucket, the label generator turns that into
reader-facing text, and the whole decision is written to the SQLite audit log before the JSON
response returns. *Appeal:* a creator posts a `content_id` + reasoning; the system looks up
the original decision, flips its status to `under_review`, logs the appeal beside the original
row, and confirms — no automated re-classification.

### API Surface
| Method | Path      | Accepts                              | Returns                                                                 |
|--------|-----------|--------------------------------------|-------------------------------------------------------------------------|
| POST   | `/submit` | `{ text, creator_id }`               | `{ content_id, attribution, confidence, signals:{llm_score,stylometric_score}, transparency_label }` |
| POST   | `/appeal` | `{ content_id, creator_reasoning }`  | `{ content_id, status:"under_review", message }`                        |
| GET    | `/log`    | —                                    | `{ entries: [ …audit rows… ] }`                                         |
| GET    | `/health` | —                                    | `{ status: "ok" }`                                                      |

## AI Tool Plan

**M3 — submission endpoint + first signal**
- *Provide to AI:* §1 (Detection Signals, esp. Signal 1) + the Architecture diagram + API Surface.
- *Ask it to generate:* the Flask app skeleton with a `POST /submit` route stub, and the
  Signal 1 (Groq) function returning `{score, rationale}`; plus the SQLite audit-log helper
  and `GET /log`.
- *Verify:* call the Groq function directly on 2–3 inputs and inspect that it returns a 0–1
  score + rationale; confirm the route returns `content_id` + placeholder confidence/label;
  confirm each `/submit` writes one structured row and `/log` reads it back.

**M4 — second signal + confidence scoring**
- *Provide to AI:* §1 (Signal 2) + §2 (Uncertainty Representation) + the diagram.
- *Ask it to generate:* the stylometric function (variance + TTR + punctuation density → one
  0–1 score) and the confidence scorer that combines both per §2 (0.65/0.35 weights +
  disagreement guard + thresholds).
- *Verify:* run the 4 assignment test inputs; confirm the generated thresholds/weights match
  §2 exactly (AI tools sometimes drift); print both signal scores separately; check clear-AI
  vs clear-human produce clearly different scores and borderline cases land in `uncertain`.

**M5 — production layer**
- *Provide to AI:* §3 (Label variants) + §4 (Appeals) + the diagram.
- *Ask it to generate:* the label generator mapping confidence→one of the three exact texts,
  and the `POST /appeal` endpoint (lookup → status `under_review` → appeal log row → confirm);
  plus Flask-Limiter config on `/submit`.
- *Verify:* confirm all three label variants are reachable and their text matches §3
  verbatim; confirm an appeal flips status and appears in `/log`; run the 12-request loop and
  confirm `429`s appear after the limit.
